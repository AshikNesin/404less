What gets reported

A link is broken when the final response is not a success: 404, 410, 500, or no response. 401 and 429 are left off the list. A login wall and a rate limit are not broken links, and treating them as broken trains you to ignore the list.

A redirect chain is two or more redirects, a loop, or a hop that switches between http and https. One hop from http:// to https:// on the same path is flagged as mixed-scheme so you can see it, and it is not called a chain. The redirect chain checker shows every status for a single URL when you need the hops.

An example of the two rows that matter:

URL Status Found on
https://docs.example.com/guide/v1 404 https://docs.example.com/
http://docs.example.com/old chain, http ↔ https https://docs.example.com/blog

The first wants a new target, or a 301 if the page moved. The 301 redirect generator writes the rule. The second wants the chain collapsed so the first hop lands on the final https URL.

What the cap is for

Each request fetches a handful of pages and stops. The page asks again with the queue, until 60 pages or the site runs out of same-host links. That stays inside a Worker’s subrequest limit, and it keeps one visitor from pointing the checker at the whole web.

  • Same host only. www and the apex are the same site. Other hosts are checked as links, not crawled.
  • robots.txt is read and Disallow rules are skipped. If it does not load, the crawl continues and says so.
  • A page request times out after a few seconds. Huge responses are cut off.
  • Private IPs, link-local, loopback, metadata hostnames, and names that resolve to those addresses are refused. So is any port other than 80, 443, 8080 and 8443.

Results are not saved as a 404less project. Run it again and the list starts over. Forty scan requests an hour from one network.

Questions

Why did it miss a page I know is broken?
The crawl stops at 60 pages, skips paths robots.txt disallows, and does not follow query strings or other hosts. A page nobody links will not be found. The self-hosted crawler also records 404s that visitors actually hit, which a crawl from the homepage cannot see.
Does it check images and scripts?
Yes, up to a budget on each page, after the links. A broken stylesheet is a broken link. Files we will not crawl as pages (images, css, pdf) are still checked when something points at them.
Can I use this in CI?
No. It is rate limited and capped, and a pull request should not depend on a public checker. The GitHub Action reads the open broken links from a 404less instance you host, which is the crawler you already run.
Is the site stored?
The scan does not write a project, a sitemap, or a history. The Worker has ordinary request logs. Self-hosting is what keeps the list, the referrers, and the alerts.
