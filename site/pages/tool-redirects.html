301 redirect generator

Paste old and new URLs, a CSV, a Netlify or Cloudflare Pages _redirects file, or vercel.json. You get rules for _redirects, vercel.json, Next.js, Nginx and Apache .htaccess, plus the mistakes that make a redirect look like it isn’t working.

    htaccess redirect generator

    Apache’s Redirect is prefix-based. This rule looks like it only moves /docs: 

    Redirect 301 /docs /docs/install

    It also redirects /docs/install to /docs/install/install, and then that URL to /docs/install/install/install. The generator emits RedirectMatch with ^ and $ so /docs does not catch /docs/install: 

    RedirectMatch 301 ^/docs$ /docs/install

    A splat becomes a capture. /blog/* → /news/:splat is RedirectMatch 301 ^/blog/(.*)$ /news/$1.

    Netlify _redirects to vercel.json

    The same three ideas, written the way each host actually matches them:

    Netlify / Cloudflare Pages Vercel and Next.js
    /blog/* /blog/:path*
    /news/:splat /news/:path*
    301 statusCode: 301
    301! (force, even if a file exists) No equivalent. The file has to be gone.
    200 (rewrite, URL stays) rewrites, not redirects

    Paste either format in the box. A vercel.json that says "permanent": true is read as 308, because that is what Vercel sends. The files this page writes use statusCode: 301 when you asked for a 301, so the status does not change on the way across.

    Why Netlify redirects look like they aren’t working

    These are the failures the warnings are for. All of them show up in real _redirects files.

    The first match wins

    Netlify, Cloudflare Pages, Vercel and Next.js stop at the first rule that matches. This file never reaches the docs rule, because /* already rewrote the request to index.html: 

    /*            /index.html   200
/docs/old    /docs/new     301

    Put the specific rules above the splat. A single-page app still wants /* /index.html 200, but it has to be last. The “Splat-first example” button loads this mistake so you can see the warning.

    The trailing slash is a different URL

    A rule for /about does not match /about/. If the site answers both, you need both rules, or one splat. Two rules that swap the slash (/about → /about/ and /about/ → /about) loop.

    301 and 308 are not the same status

    permanent: true in vercel.json and in next.config.js is a 308. A 308 keeps the HTTP method (a POST stays a POST). A 301 lets the client turn it into a GET. Browsers follow both, but a form POST, a webhook, or a crawler that records the status will not treat them as the same redirect. If you want a 301, set statusCode: 301. Don’t set permanent as well and hope.

    A file at the old path wins

    On Netlify and Cloudflare Pages a real file is served before _redirects, unless the status has a force flag: /old /new 301!. Vercel has no force flag. Delete the file, or the redirect never runs. The other formats leave the ! out and say so.

    200 is not a redirect

    /docs /docs/index.html 200 rewrites the request. The browser stays on /docs. Search engines do not pass equity the way they do for a 301, and vercel.json puts that line in rewrites, not redirects.

    Questions

    Where does the _redirects file go?
    In the publish directory, named exactly _redirects. For Cloudflare Pages that is the build output. For Netlify it is the same, unless you declare the rules in netlify.toml instead. A file named redirects or sitting in src/ is never read.
    Do Cloudflare Pages and Netlify use the same file?
    The static rules do: from to status, splats, and :splat. Netlify’s conditions (Country=us, Role=admin) are not in Cloudflare Pages. This generator drops them and warns, because the other hosts have no place to put them.
    Can I paste a whole vercel.json?
    Yes. Redirects and rewrites are converted. Other keys (headers, crons, functions) are left out, with a warning, so you can merge the new redirects array into the file you already have.
    What about query strings?
    /go?id=:id /landing/:id 301 is a Netlify pattern. Vercel expresses the same idea with a has condition, and Nginx only keeps the original query when the destination doesn’t set one ($is_args$args). The generator keeps the query in the path and warns that it will not match the same way everywhere.
