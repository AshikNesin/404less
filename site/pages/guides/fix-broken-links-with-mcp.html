Find and fix broken links with Claude Code or Cursor.

The MCP server answers four read-only questions: which sites you have, which URLs are broken, what the closest replacement is, and who linked there. The agent writes the fix in your repo. 404less never receives a git token.

Connect Claude Code or Cursor

Create a key under API & MCP. It is shown once and stored hashed. The server is streamable HTTP, protocol 2025-03-26, POST only. GET and DELETE get 405. The header is Authorization: Bearer 404l_….

Claude Code, the same command as on /agent:

$ claude mcp add --transport http 404less https://your-404less.example/mcp \
    --header "Authorization: Bearer 404l_…"

Cursor, Claude Desktop, and anything else that reads an MCP config:

{
  "mcpServers": {
    "404less": {
      "type": "http",
      "url": "https://your-404less.example/mcp",
      "headers": { "Authorization": "Bearer 404l_…" }
    }
  }
}

A missing or wrong key is a JSON-RPC error, HTTP 401, unauthorized: provide a valid API key as bearer token. Revoke the key on the same settings page; the next call fails immediately.

The four tools

Names and arguments are the TOOLS array in apps/web/src/server/api/mcp/mcp.routes.ts. Every call is scoped to the team that owns the key. site accepts a site id, a domain, or a name, case-insensitive.

Tool Arguments What comes back
list_sites none id, name, domain, and the count of open broken links
list_broken_links site required. status is open (default), resolved, ignored, or all. since is an ISO timestamp. limit defaults to 50 and stops at 200 Most hits first. Each row has the URL, title, status, who detected it (visitor, crawler, or both), hits, HTTP status, first and last seen, the stored suggestion, and the page the crawler found the link on
get_suggestions site, url Up to five ranked replacements from suggestFor
get_link_details site, url Hits, status, last crawler check with the redirect chain, top referrers, pages that link to it, and suggested fixes

An unknown site comes back as { "error": "unknown site \"…\"" } with isError: true, so the agent can read it. There is no tool that writes a redirect, ignores a link, or edits a file.

A raw call, useful when you want to see the JSON before involving an agent:

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "list_broken_links",
    "arguments": { "site": "docs.example.com", "limit": 20 }
  }
}
$ curl -s https://your-404less.example/mcp \
    -H "Authorization: Bearer 404l_…" \
    -H "Content-Type: application/json" \
    -d @call.json

A prompt that matches the product

The “Ask your agent” tab builds this text in redirect-snippet.tsx. It asks for a 301 in whatever file the repo already uses, an update to the hrefs, and a small PR. Paste it after the MCP server is connected so the agent can call list_broken_links for the rest of the list in the same session. 

Fix this broken link.

Broken URL: https://docs.example.com/docs/old
Replace it with: https://docs.example.com/docs/new

Do three things:
1. Add a 301 redirect from /docs/old to /docs/new in whatever redirect mechanism this repo uses (look for _redirects, vercel.json, next.config.js, nginx config, or .htaccess).
2. Find every page that links to https://docs.example.com/docs/old and update the href to https://docs.example.com/docs/new.
3. Open a PR with both changes; keep it minimal.

For a batch, the prompts on /agent are the ones that have been written against these tools: top links this week as vercel.json rules, every href pointing at one dead URL, a referrer summary. The platform file still has to be the one the repo uses. permanent: true on Vercel is a 308, which the Vercel guide explains. The agent prompt says “301” because that is the string in agentPrompt. On Vercel, tell it to use statusCode: 301 if you truly want a 301, or leave permanent: true if a 308 is acceptable. Google treats those two as the same permanent signal.

After the PR merges, resolve the rows in the dashboard or let the crawler see a successful response and resolve them. Ignored rows stay ignored and do not alert.

What the key can also do

MCP is read-only. The same bearer token is accepted by the dashboard API under /api/v1, because session.middleware.ts treats it as the team owner. That API includes reads (GET /api/v1/sites, GET /api/v1/sites/:id/links, the CSV export, link details) and writes (starting a crawl, changing a link’s status, creating a site). Give the key only to an agent you would allow to call those routes. A client that should only list broken links still holds a key that can do more, until a narrower key exists.
