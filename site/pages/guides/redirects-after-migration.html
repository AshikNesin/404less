Redirects after a site migration or URL restructure.

One old path, one new path, one permanent hop. Everything else in a migration is bookkeeping so that list is complete, and a way to hear about the URLs you missed.

Inventory Map Status Ship the file After launch

Inventory the URLs that already exist in the wild

  • The current sitemap, and the previous one if you still have the file.
  • Paths in analytics that received a session in the last few months.
  • URLs other sites link to. A crawler of your own pages misses those until someone hits them.
  • Once 404less is on the old 404 page, the visitor log (not_found_events, pruned on the retention schedule) and the broken-link list. Hits are the paths people still request.

A sitemap import fills known_urls, which is also what suggestions are ranked against. Import the new sitemap after the new URLs exist, so a suggestion is a page you kept.

Map each old URL to one outcome

  • A specific new URL, when the content moved or was renamed.
  • 410 or 404, when nothing replaced it. A 410 says the removal is intentional. Google’s status-code doc treats 404 and 410 the same for indexing: the URL comes out of the index.
  • Leave it alone when the path did not change.

Skip “send everything unknown to the homepage.” That serves one page for many old URLs. The soft 404 guide is why that is a weak map. A close page is a real target. No close page means a 404.

Update the hrefs inside the site in the same change as the redirect. The redirect saves bookmarks and other people’s links. Internal links should point at the new path so you are not one hop away from yourself. The agent prompt in redirect-snippet.tsx asks for both. The MCP guide is how to hand the list to Claude Code or Cursor.

Pick the status once

A move that is staying is a permanent redirect. Google treats 301 and 308 as the same strong signal, and 302 and 307 as a weak one. They follow up to 10 hops and index the final URL, ignoring the body of the redirecting URLs. Chains waste hops and add a round trip. Point the old path at the final path.

Temporary (302 or 307) is for a move you will undo. A launch-week “we might revert” that you forget becomes the signal Google keeps.

Ship the file your host actually reads

The five strings below are what the dashboard generates for /docs/old → /docs/new. Use the one that matches the repo.

Cloudflare Pages and Netlify

# _redirects (Cloudflare Pages / Netlify)
/docs/old  /docs/new  301

Pages defaults to 302 if you drop the code, caps the file at 2,000 static rules plus 100 dynamic ones, and will not take a Netlify-style query condition. Netlify defaults to 301, processes _redirects before netlify.toml, and shadows a rule when a file exists unless you force it. Both are written up in the Pages and Netlify guides. A large Netlify list that fails the deploy is the “10,000 rules” note in their overview: use splats where a whole prefix moved.

Vercel and Next.js

{
  "redirects": [
    {
      "source": "/docs/old",
      "destination": "/docs/new",
      "permanent": true
    }
  ]
}
// next.config.js
module.exports = {
  async redirects() {
    return [{ source: "/docs/old", destination: "/docs/new", permanent: true }];
  },
};

permanent: true is a 308. For a migration of thousands of one-to-one paths, Vercel bulk redirects are the feature built for that, on Pro and Enterprise, with permanent defaulting to false (307) in that system. Read Vercel redirects before you generate a CSV, or every row is temporary.

Nginx and Apache

location = /docs/old {
  return 301 /docs/new;
}
# .htaccess
Redirect 301 /docs/old /docs/new

location = is an exact match. A prefix move is a different nginx block; this generator does not emit one. Apache’s Redirect matches the path prefix, so Redirect 301 /docs/old /docs/new also covers /docs/old/chapter. That is Apache’s behaviour, and it surprises people who expected an exact path. Use RedirectMatch when you need an exact line.

After launch

  • Keep the old host answering with the redirects until logs go quiet. Cutting the old domain over to a parking page on day one drops the map.
  • Submit the new sitemap in Search Console.
  • Put the embed on the new 404 page so the paths the map missed show up with a referrer. That is tracking 404s.
  • Re-crawl. A link that now returns 200 or 300 is resolved by the crawler. A link that still 404s stays open.
  • Look at redirect chains once, with the tool above or with curl -sI -L.
