A custom 404 page for Hugo, Next.js, and Astro.

Each framework already has a file for this. The useful part is a real 404 status, a title a human can read, and three links to pages that exist, chosen from the path the visitor typed.

The snippet Hugo Next.js Astro Where the suggestions come from

One script, three files

Plain HTML, from snippetFor in apps/web/src/client/features/sites/platform-snippet.tsx, with the origin filled in: 

<script src="https://your-404less.example/embed.js" data-site="SITE_KEY" defer></script>

The script reports location.href and asks /api/suggestions for up to three URLs. It stays quiet unless the page looks like a 404. The checks are listed in the Cloudflare Pages guide and in the comment at the top of embed-script.ts.

App Router not-found pages keep the root layout’s title, so a title check is the wrong signal. The dashboard’s Next.js snippet sets data-404="true" for that reason. Use the same attribute on Hugo and Astro when the layout title is the site name. data-404="false" turns detection off.

Hugo

Hugo’s docs say to put the template at layouts/404.html. Their example is a main block, which assumes a base template that renders that block inside the body: 

{{ define "main" }}
  <h1>404 Not Found</h1>
  <p>The page you requested cannot be found.</p>
  <p><a href="{{ site.Home.RelPermalink }}">Return to the home page</a></p>
  <script src="https://your-404less.example/embed.js" data-site="SITE_KEY" data-404="true" defer></script>
{{ end }}

The {{ define "main" }} line is Hugo’s, from the custom-404 doc. The script tag is the 404less snippet with data-404="true" added. If your site has no base template, write a full HTML document in layouts/404.html instead of a define block. Multilingual sites use layouts/404.en.html and the other language codes, which is also on that doc.

Hugo’s doc is explicit that the production server is what turns a missing path into this template, and that hosts differ. On Cloudflare Pages the published file is public/404.html (or whatever your publishDir is), and Pages uses it as the not-found page. Confirm the status with curl -sI. A 200 here is a soft 404, covered in the Search Console guide.

Next.js

This is the dashboard snippet, copied from snippetFor(..., "next"). It is the App Router file app/not-found.js. The comment in the source says the Pages Router file is pages/404.js, and the same next/script element works there. 

// app/not-found.js (App Router)
import Script from 'next/script'

export default function NotFound() {
  return (
    <>
      <h1>404</h1>
      <Script src="https://your-404less.example/embed.js" data-site="SITE_KEY" data-404="true" strategy="afterInteractive" />
    </>
  )
}

Next’s own doc: before streaming starts, this returns status 404. After streaming has started, the status stays 200 and the not-found UI is written into the body. A 200 is the soft-404 case. global-not-found.js is experimental, needs experimental.globalNotFound, and must return a full document because it skips your root layout. Put the script in that file too if you use it, and give the document a title that contains “404” or keep data-404="true".

Redirects for URLs you still want to support belong in next.config.js, not in this component. permanent: true there is a 308. See Vercel redirects.

Astro

Astro’s pages doc: create src/pages/404.astro or 404.md. The build output is 404.html. “Most deploy services will find and use it.” 

---
// src/pages/404.astro
---
<html lang="en">
  <head>
    <title>404 Not Found</title>
  </head>
  <body>
    <h1>404 Not Found</h1>
    <p>That page doesn’t exist.</p>
    <script
      is:inline
      src="https://your-404less.example/embed.js"
      data-site="SITE_KEY"
      data-404="true"
      defer
    ></script>
  </body>
</html>

Astro processes a <script> that has no attribute other than src: it can bundle it and set type="module". Any other attribute leaves the tag alone, and is:inline is the documented way to opt out on purpose. The embed is a file on your 404less host. It should be left as a normal script tag. data-site would already opt out; is:inline keeps that obvious the next time someone tidies the tag.

src/pages/500.astro is a different page, for errors while rendering on-demand routes, and it is not used for prerendered pages. Do not put the 404 snippet only there and expect missing URLs to report.

Where the three links come from

Suggestions are known URLs for that site: sitemap import, plus pages the crawler fetched. suggest.ts scores the broken path against each candidate with token overlap and a normalised edit distance, keeps a shortlist of 60, and returns at most three results at or above 0.2. A title shared by three or more known pages is dropped, so a repeated “Home” title does not decorate every suggestion. The card says “Looking for something?” unless you set data-title.

Import a sitemap or run a crawl before you judge the card. With an empty known_urls table the widget has no links to draw. The hit is still recorded.

Styling stays outside the shadow root: .f404less { --f404-accent: #1f1f23; } and the other variables listed on /embed. data-max is 1–5, default 3. data-track="false" shows suggestions and skips the hit report.
