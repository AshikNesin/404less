301 vs 308

Vercel’s vercel.json reference, checked 10 Nov 2026, defines permanent like this: when it is true the status is 308, when it is false the status is 307. The default of permanent on a configuration redirect is true. So a rule that only sets source and destination is a 308.

statusCode is how you ask for something else. Vercel’s example of a 301 uses statusCode: 301 and does not set permanent. The reference says the two properties cannot be used together. Allowed override codes on bulk redirects are 301, 302, 303, 307, and 308. The configuration reference shows 301 in the same role.

Next.js documents the same pair, and says why they picked it:

  • permanent: true → 308, which clients and search engines may cache
  • permanent: false → 307, temporary, not cached as a permanent move

A 301 or a 302 may be turned into a GET by the client. A 307 or a 308 keeps the method and the body. That matters for a public API. For a browser following a link, the request was a GET either way.

Google’s status-code doc says their crawlers treat 308 as equivalent to 301, and 307 as equivalent to 302. They also say the codes are semantically different and you should send the one you mean, because other clients are not Googlebot. A 308 is a fine permanent signal for Google. Send 301 when a client you care about mishandles 308, or when a written policy says “301”.

Vercel’s CDN also emits its own 308s before your rules run: consecutive slashes are collapsed (/blog//post → /blog/post). Paths are case-sensitive at the CDN. A project-level redirect matches case-insensitively unless the project turns case sensitivity on, or the deployment’s vercel.json contains rewrites, redirects, or headers, which makes those rules case-sensitive.

vercel.json vs next.config.js

Vercel’s configuration-redirects doc says a Next.js project should use next.config.js and does not need vercel.json for these rules. Both accept source, destination, and permanent. Next.js also supports :slug, :slug*, and a regex in parentheses. Redirects are checked before files in public/ and before pages. Query strings on the request are passed through to the destination.

On the Pages Router, these redirects do not apply to client-side Link navigation unless a proxy (what older docs called middleware) also matches. A full page load still hits them.

Wildcards, header matches, and country matches (x-vercel-ip-country) belong in this configuration layer. Bulk redirects, below, do not do wildcards.

Bulk redirects

Vercel’s bulk-redirects doc says they are for thousands of simple path-to-path rules, with no wildcard and no header match. They run before any other route in the deployment. You can ship them at build time with bulkRedirectsPath in vercel.json (one file, or a folder of up to 100 CSV, JSON, or JSONL files), or change them later from the dashboard, the API, or the CLI without a redeploy. The CLI examples require Vercel CLI 50.1.0 or newer for the full set, including vercel redirects import.

The field defaults are not the configuration-redirect defaults:

Field Default What you get
permanent false 307. Set true for 308
statusCode 307, unless permanent says otherwise 301, 302, 303, 307, or 308. Overrides permanent
caseSensitive false
preserveQueryParams false The query string is dropped unless you set this

A CSV may use t and f for the booleans. source ignores any query string you put in it. Each of source and destination is capped at 2,048 characters.

Availability, from that same page: Pro and Enterprise. Hobby does not include them. Pro includes 1,000 bulk redirects, Enterprise includes 10,000, extra capacity is sold in groups of 25,000 at $0.002 per month per group, and a project can hold at most 1,000,000. Requests served by a bulk redirect are billed like any other request.

For a docs rename of twenty URLs, a redirects array is the simpler file and it works on Hobby. Bulk is the one that stays fast at migration size and can be edited without a deploy.

Middleware, when the rule is not a static map

Vercel’s redirects overview lists Middleware as the place for dynamic redirects that should change without a redeploy (they pair it with Global Config). Configuration redirects and bulk redirects are the static maps. A function or a route handler is the escape hatch when the decision depends on a cookie, a flag, or a lookup.

NextResponse.redirect takes the status as the second argument. This sends a 301 for one path: 

import { NextResponse } from "next/server";

export function middleware(request) {
  if (request.nextUrl.pathname === "/docs/old") {
    return NextResponse.redirect(new URL("/docs/new", request.url), 301);
  }
}

What the 404less dashboard copies

The Vercel tab stringifies permanent: true. That is a 308, which matches Vercel’s and Next’s default permanent redirect. It is not a 301. If you need a 301, change the object to statusCode: 301 and drop permanent. 

{
  "redirects": [
    {
      "source": "/docs/old",
      "destination": "/docs/new",
      "permanent": true
    }
  ]
}

The Next.js tab is the same rule, in next.config.js:

// next.config.js
module.exports = {
  async redirects() {
    return [{ source: "/docs/old", destination: "/docs/new", permanent: true }];
  },
};

Both strings are generated by apps/web/src/client/features/links/redirect-snippet.tsx. The trailing newline on the Next.js snippet is part of that generator.
