Fixing soft 404 errors in Google Search Console.

A soft 404 is a success status on a page that looks like a failure. Google says so in the status-code documentation. The fix is the status line, then the body.

What Google calls a soft 404 How static hosts produce one What to send instead How to check

What Google calls a soft 404

On the page How HTTP status codes affect Google’s crawlers, a 2xx means Google will consider the body. Then this sentence: if the content suggests an error, or the page is empty, or the page is an error message, Search Console shows a soft 404. A 200 does not promise indexing. It does put the body in front of the indexer.

A real 404 or 410 is handled with the other 4xx codes (except 429). Google does not index them. A URL that used to be indexed and now returns 4xx is removed over time. The bytes of a 404 page are ignored. That is a hard 404, which is what you want for a URL that should not exist.

The dedicated help article that used to live at /search/docs/appearance/soft-404-errors returned “not found” when this draft was written. The status-code page is the citation until that article has a working URL again.

How a static host produces one

Cloudflare Pages, when the build has no top-level 404.html, serves the root document for any path that is not an asset. That is in their serving-pages doc. The visitor asked for /blog/retired-post and received the homepage. If that response is a 200, it matches Google’s soft-404 description whenever the homepage is a poor stand-in for the missing URL, and it matches it directly when your SPA then renders an error state at that URL.

Netlify’s /* /index.html 200 is the same shape: status 200, body of whatever index.html is, address bar unchanged. Their docs call 200 a rewrite. Put specific 301s above that line, and ship a 404.html for paths that should die. The order is in Netlify redirects not working.

Next.js, from the not-found.js doc: before streaming starts, the status is 404. After streaming has started, the status stays 200 and the not-found UI is rendered into the response. Next injects a meta tag in both cases. The tag’s name did not survive the text extract of that doc, so it is not repeated here. A 200 with a “not found” heading is the soft-404 shape Google describes.

[ASHIK: open https://nextjs.org/docs/app/api-reference/file-conventions/not-found and write the meta tag’s name. The 404less embed does not treat a robots meta as a 404. It looks at data-404, metas named 404less, prerender-status-code, or render:status_code, and the title. That is why the product snippet sets data-404="true".]

404less’s crawler will not flag these. isWorking in apps/web/src/server/api/crawl/checker.ts treats every 2xx and 3xx as a working link (401 and 429 too, plus any status you listed under ignored codes). A soft 404 is a successful response by that test. The embed only runs when the page is detected as a 404, so a homepage served for a missing path does not report the hit either.

What to send instead

Pick one, per URL:

  • The page should exist. Make the URL return its own content with a 200, and a title that is not an error.
  • A specific page replaced it. Send a permanent redirect, one hop. 301 vs 308 on Vercel and the migration checklist. Google follows up to 10 hops and indexes the final URL. A 301 and a 308 are both strong permanent signals in their status-code doc.
  • Nothing replaced it. Return 404 or 410, with your custom 404 page as the body. The status is what removes the URL. The body is for the human who followed an old link.

Pointing dozens of retired URLs at / gives Google the homepage for each of them. Prefer a close replacement, or a 404, so the indexed URL and the content agree.

Related tool: 404 page checker for “is this a 200 with an error body, or a real 404?”. That path may 404 until the tools PR lands.

How to check a URL before you trust the report

curl -sI https://example.com/blog/retired-post

Read the first status line, and follow Location if you see one. curl -sI -L shows the hop list. Then open the URL in a browser and read the title. Search Console’s URL inspection is the same request from Google’s side. After you change the status, the report lags the crawl. A 404 you shipped today can sit in the soft-404 report until Google fetches it again.
