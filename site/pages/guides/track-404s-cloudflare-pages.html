How to track 404 errors on Cloudflare Pages.

Pages will show a visitor your 404.html. It will not hand you a list of which paths they asked for. Put one script tag on that file and the path, the referrer, and a few close matches are yours.

What Pages does The script Any static host When you already know the fix

What Cloudflare Pages does with a missing file

Cloudflare’s serving-pages doc says a 404.html in the output is the page shown when a file is missing. Pages looks in the requested directory, then walks up to /404.html. A /blog/404.html covers /blog/… and the root file covers the rest.

If the project has no top-level 404.html, Pages treats the site as a single-page app and serves the root document for any path that is not a real asset. That is how a missing URL becomes a 200 of your homepage. Search Console calls a 200 that looks like an error a soft 404. The soft 404 guide is the longer version. Put a real 404.html in the output before you worry about tracking.

The script tag

This is the install snippet from the dashboard, aimed at your Worker. Replace the origin and the site key. The key is on Site settings → Install. 

<script src="https://your-404less.example/embed.js" data-site="SITE_KEY" defer></script>

On Cloudflare Pages the tag goes in 404.html before </body>. Hugo writes that file from layouts/404.html. Astro writes it from src/pages/404.astro. Both are spelled out in the custom 404 page guide.

The script, in apps/web/src/server/api/embed/embed-script.ts, does nothing until it decides the page is a 404. First match wins:

  • data-404 on the script tag itself (anything other than false or 0)
  • window.__404less.is404
  • data-404 on <html> or <body>
  • a meta tag named 404less, prerender-status-code, or render:status_code whose content matches “404” or “not found”
  • a document title that contains “404”, “not found”, or “page doesn’t exist”

A Pages 404.html whose <title> says “Page not found” is enough. If the layout title is your site name, set data-404="true" on the script. That is what the Next.js snippet in the dashboard does, for the same reason.

A hit is a POST to /api/track with the URL, the referrer, and the title. The body is text/plain so the browser skips the preflight. Then GET /api/suggestions returns up to three known URLs. Suggestions come from known_urls (a sitemap import plus pages the crawler fetched). The ranker scores path tokens and edit distance, drops a title that three or more pages share, and hides anything under 0.2. Until a sitemap or a crawl has run, the card has nothing to show. Details are on the embed page.

The same idea on any static host

The host has to return your 404 document for a missing path, and the browser URL has to stay the URL the visitor typed. The script reports location.href. If the host redirects the browser to /404.html, every miss is recorded as that one path.

Netlify picks up a 404.html in the publish directory with no redirect rule. That is in their redirect-options doc, and the Netlify redirects guide covers the case where a /* /index.html 200 rule swallows the 404 first.

Nginx, internal redirect, URL unchanged:

error_page 404 /404.html;

Apache:

ErrorDocument 404 /404.html

Put the same script tag in that HTML file. Options (data-mode, data-theme, data-max, and the rest) are the table on /embed.

When you already know the new URL

Cloudflare Pages reads a _redirects file in the static output. One rule per line: source, destination, optional status. The default status is 302. A comment line starts with #. The file allows 2,000 static redirects and 100 dynamic ones, and each line is limited to 1,000 characters. The top rule wins. Redirects run even when a file exists at that path. Query-string matching is not supported. Status 404 rewrites of the Netlify kind are not supported.

The rule the 404less link page copies is explicit about 301, which matters here because the Pages default is 302. This string is what redirect-snippet.tsx returns for /docs/old → /docs/new: 

# _redirects (Cloudflare Pages / Netlify)
/docs/old  /docs/new  301

Netlify’s file looks the same and defaults to 301, and an existing file shadows the rule unless you force it. Copying a Netlify article onto Pages, or the other way around, is a common way to ship the wrong status. The Netlify page is next to this one on purpose.

Placeholders and a single splat are supported (/blog/* → /news/:splat). Static rules should sit above dynamic ones. Pages Functions do not see _redirects; the docs say to move those rules into the Function.
