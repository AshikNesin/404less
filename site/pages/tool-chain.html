Redirect chain checker

Redirect chain checker

Enter a URL. We request it from the server, follow each Location ourselves, and list the hop, the status, and whether the chain loops, runs long, or switches between http and https.

    What a chain looks like

    One redirect is normal. This is a chain, and it also changes scheme in the middle:

    Hop Status URL
    1 301 http://docs.example.com/v1/install
    2 301 https://docs.example.com/v1/install
    3 200 https://docs.example.com/install

    The first hop only adds HTTPS. The second hop is the real move, from /v1/install to /install. Browsers will follow it. Crawlers spend two round trips, and any tool that stops after one hop records the wrong URL. Fold it into a single 301 from the http URL straight to https://docs.example.com/install.

    A loop is the same URL twice: /a → /b → /a. We stop when a URL repeats, instead of following it until the browser gives up. “Too long” means the chain was still a redirect at the eighth hop.

    http to https in the middle

    HTTPS belongs on the first hop, at the edge (Cloudflare “Always Use HTTPS”, the host’s canonical redirect, or an HSTS header). If a later rule sends the visitor back to http, the chain mixes schemes and the lock in the browser flickers. The checker flags any chain that contains both.

    A single hop from http:// to the same path on https:// is not marked as a chain. It is the hop you want. It is marked as mixed-scheme so you can see it.

    Questions

    Why not let the browser follow the redirect?
    The browser collapses the chain. You see the final page and, at most, that “something redirected”. The status of each hop is the part that tells you whether a 302 temporary redirect is sitting in front of a 301.
    Which statuses count as a redirect?
    301, 302, 303, 307 and 308, anything from 300 to 399 with a Location header. A 200 that says “you are being redirected” in the HTML is not a redirect. It is a page, and a soft 404 checker is the tool for that.
    Will this request private or internal addresses?
    No. Loopback, link-local, private ranges, and hostnames that resolve to them are refused before the request. So are userinfo URLs (https://user:pass@host) and ports other than 80, 443, 8080 and 8443. Each redirect is checked again, so a public URL cannot bounce the checker onto 127.0.0.1 or the cloud metadata address.
    How many checks can I run?
    20 an hour from one network. The point is to debug a URL you are looking at, not to crawl the web. For a whole site, use the broken link checker, or self-host 404less and let the crawler do it on a schedule.
