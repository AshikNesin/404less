404 logging for non-WordPress sites.

On WordPress, the Redirection plugin logs 404s and writes the redirects. On a Hugo, Next.js, Astro, or plain static site there is no plugin slot. The 404 template and the host’s redirect file are the same job.

What the plugin does What you do without WordPress Using 404less on WordPress anyway

What the Redirection plugin actually ships

The listing at wordpress.org/plugins/redirection (John Godley, page last modified 19 Sep 2026 in the fetch) describes a free plugin. The same page says there is no premium version. Full docs are at redirection.me. PHP 7.4 through 8.5.

From that listing:

  • Create and manage redirects, including regular expressions, without writing Apache or nginx by hand. If the site uses permalinks, any URL can be redirected.
  • Match query parameters, and pass them through.
  • Optionally create a redirect when a post or page permalink changes. A separate “migrate permalinks” flow takes the old structure.
  • Conditions: login state, capability, browser, referrer, cookie, header, your own filter, IP, another domain on the same server, and “this page is a 404”.
  • A log of redirects with hit counts, browser, and referrer. IP collection can be reduced or turned off. Logs export.
  • A 404 log. Errors can be grouped, and redirected in bulk.
  • Redirects are handled by WordPress by default. They can be written to .htaccess for Apache, or exported as nginx rewrite rules.
  • Import and export: htaccess, nginx, JSON, CSV, WP-CLI, and imports from several other redirect plugins.

That is a complete “log the 404, then make the redirect” loop, and it lives in wp-admin. It also only runs where WordPress runs. A Hugo site, a Next.js app, an Astro site, and a bucket of HTML have nowhere to install it.

The same loop on a site that is not WordPress

Two pieces, both files you already deploy:

  1. The 404 template records the hit. Hugo’s file is layouts/404.html, Next.js uses app/not-found.js or pages/404.js, Astro uses src/pages/404.astro. The script and the reason for data-404="true" are in the custom 404 guide. Cloudflare Pages and other static hosts are in tracking 404s on Pages.
  2. The redirect lives in the host’s file, not in a database. The dashboard copies _redirects, vercel.json, next.config.js, an nginx location, or an Apache Redirect. Those strings, and the status-code traps, are in the Netlify, Vercel, and migration guides.

What you do not get, relative to the plugin listing: automatic creation of a redirect when a permalink changes, conditional redirects based on login or IP, and a log of every successful redirect (404less logs the miss, and the crawler’s history of checks, not every 301 your host served). What you do get that the plugin cannot do outside WordPress: the same list for a static host, suggestions from your sitemap, and a read-only MCP server for Claude Code or Cursor (that guide).

Related tools, which may 404 until the tools PR lands: redirect rule generator, 404 page checker.

A WordPress site can still run the embed

The install UI in this repo has a WordPress tab. The guidance next to it says to add the script to 404.php in the theme, before <?php get_footer(); ?>, or to use a plugin such as WPCode. That is platform-snippet.tsx. The script will record hits and show suggestions. It will not write .htaccess for you, and it will not notice that you changed a permalink.

If the site is WordPress and the plugin already logs 404s and manages redirects, you already have the loop the listing describes. Adding 404less on top is a second log. The reason to do it is the MCP tools or a redirect snippet aimed at a non-PHP host, which a normal WordPress site is not using.
