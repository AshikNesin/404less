404 and soft 404 checker

Enter a URL. We fetch it, then fetch a random path on the same host that should not exist. A real 404 is a 404 or 410. A soft 404 is a missing page that still returns 200, or the same page the rest of the site returns.

What Search Console means by soft 404

Google requested a URL, got a response that looks like “this page is not really there”, and dropped the URL from the index. The Page indexing report then says Soft 404. The usual cause is a missing page that returns 200 OK. Sometimes it is a 301 to the homepage, or a 200 whose title is “Page not found”. The status is what Google asked for and did not get. A pretty 404 template with a 200 status is still a soft 404.

Two hosts, same symptom, different bugs:

What you requested Real 404 Soft 404
/docs/install (the page exists) 200 200
/docs/instll (it does not) 404 200, often the homepage or the app shell
What Google does Keeps the real URL, drops the typo Drops both, and reports a soft 404

The fix is the status, not the design. Return 404 (or 410 when the page is gone on purpose). The body can still offer search and links. Use a 301 only when there is a real replacement, and point it at that page, not at the homepage.

Where the 200 comes from

Single-page apps do this by default. Cloudflare Pages with “single page application” not-found handling, Netlify’s /* /index.html 200, and an nginx try_files $uri /index.html all serve the app shell with 200 for every path. The app may then render a “not found” view. The HTTP status never changes, so Google sees a 200.

Give unknown paths a real 404. On Cloudflare Pages that is a 404.html and not-found handling set to “404 page”, not the SPA fallback, for any site that is not actually a client-side app. A 200 rewrite can stay for the routes the app owns; it should not be the catch-all in front of your docs.

noindex on a 200 is not a substitute. Google may still call the URL a soft 404, and you have spent a crawl on a page you then asked it to ignore. Status 404 already says “don’t index this”.

Questions

Why fetch a second, random path?
A 200 on its own does not mean the page is missing. It means the URL returned a page. The second request is a path you did not publish. If it returns the same 200, the same title, or the same body, the host is not telling anyone the page is gone.
My URL is a real page, but the result says the host returns 200 for missing paths.
Then this URL is fine and the catch-all is not. Unknown URLs on that host will show up as soft 404s in Search Console even though the page you checked is real. Fix the fallback, not this page.
Does a 301 to the homepage count?
If the missing path lands on the same final URL as the one you entered, both are the same document. That is the “everything redirects home” soft 404. A 301 to a specific replacement, with missing paths returning 404, is reported as a redirect instead.
Can I choose the missing path?
Yes. Leave the field empty and we request /404less-probe- plus a random id. If you know a path that used to exist, put it there (it has to start with / and stay on the same host).

Show visitors a real 404, and record it.

The 404less embed sits on a page that returns 404. It reports the hit and offers the closest real pages. A 200 with a “not found” message never reaches it. Self-host it on Cloudflare’s free tier.
