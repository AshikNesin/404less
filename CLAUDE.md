## Project Overview

This is "404less" - a 404 monitoring SaaS platform. It's a monorepo with two main applications: a React client app and a FastAPI server, plus a separate marketing website.

**Architecture:**
- **Server** (Port 9000): FastAPI backend that serves the client app and provides APIs
  - In development: proxies to Vite dev server (port 9001) for frontend
  - In production: serves static built files from client/
  - All API routes use `/api/*` prefix
- **Client**: React + Vite + TypeScript + Tailwind + shadcn/ui (authenticated app)
  - Development: Vite dev server on port 9001 (proxied through server)
  - Production: built to `server/static` and served by server
- **Website**: React + Vite + TypeScript + Tailwind + shadcn/ui (marketing site)
  - Separate deployable static site (Netlify/Vercel)
  - Port 9002 in development
- **Database**: PostgreSQL (via Docker)
- **Package managers**: pnpm (client/website), uv (server)
- **Code quality**: Biome (client/website), Ruff (server)

## Development Commands

### Full Stack Development
```bash
# Start everything (database + server + client dev)
# Access at: http://localhost:9000
make dev

# Start individual services
make db           # Database only
make server       # Server only (port 9000)
make client       # Client Vite dev server only (port 9001)
make dev-client   # Alias for client
make website      # Website only (port 9002)
```

### Database Operations
```bash
# Run database migrations
make migrate

# Seed database with initial data
make seed
```

### Build for Production
```bash
# Build client and output to server/static
make build

# Then run server in production mode
cd server
ENV=production uv run uvicorn app.main:app --host 0.0.0.0 --port 9000
```

### Server Commands (run from server/ directory)
```bash
# Install dependencies
uv sync

# Start development server (proxies to Vite on port 9001)
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 9000

# Run tests
uv run pytest

# Lint code
uv run ruff check .

# Format code
uv run ruff format .

# Create migration
uv run alembic revision -m "description"

# Run migrations
uv run alembic upgrade head
```

## Key Development Patterns

### How Development Works

1. Run `make dev` to start everything
2. Client Vite dev server starts on port 9001
3. Server starts on port 9000 and proxies all non-API requests to Vite
4. Access the app at http://localhost:9000
5. HMR works through the proxy
6. API calls use `/api/*` prefix and are handled by server

### How Production Works

1. Run `make build` to build client to `server/static`
2. Server serves static files from `server/static`
3. API routes still use `/api/*` prefix
4. Single server handles everything on port 9000

### API Development Workflow
1. Modify FastAPI endpoints in `server/app/api/v1/`
2. All API routes must use `/api` prefix (handled by router prefix)
3. Update Pydantic schemas in `server/app/schemas/`
4. If database changes: create Alembic migration
5. Regenerate client types: `cd client && pnpm typegen`
6. Update client components to use new types

### Database Changes
1. Modify models in `server/app/db/models.py`
2. Generate migration: `cd server && uv run alembic revision -m "description"`
3. Apply migration: `make migrate`
4. Update schemas if needed

### Client API Calls
- All API calls use `/api/*` prefix (e.g., `/api/v1/auth/login`)
- API client is in `client/src/lib/api.ts`
- Types are auto-generated from OpenAPI spec
- No proxy needed in client - server handles everything
- Website does NOT connect to the API - it's a static marketing site

### Code Quality Standards
- Server: Use Ruff for linting and formatting (`uv run ruff check .` and `uv run ruff format .`)
- Client/Website: Use Biome for linting and formatting (`pnpm lint` and `pnpm format`)
- Line length: 100 characters for all codebases

## Environment Setup

### Server Environment
Create `server/.env` from `server/.env.example`:
```bash
DATABASE_URL=postgresql+psycopg://dev:dev@localhost:5432/app
BACKEND_HOST=0.0.0.0
BACKEND_PORT=9000
CORS_ORIGINS=http://localhost:9001
ENV=development
VITE_DEV_SERVER_URL=http://localhost:9001
SECRET_KEY=dev-secret-key-change-in-production
```

**Note:** Docker Compose automatically provides sensible defaults for PostgreSQL. Only the `DATABASE_URL` and `SECRET_KEY` are required.

### Client Environment
Create `client/.env` from `client/.env.example`:
```bash
# API calls use /api prefix (handled by server)
VITE_API_BASE_URL=/api
```

### Website Environment
The website is a static marketing site and doesn't require environment variables. It can be deployed to any static hosting platform (Netlify, Vercel, etc.).

## Local Development Ports

- **Server**: http://localhost:9000 (main app - serves client + APIs)
  - In development: proxies to Vite dev server for frontend
  - In production: serves static files from server/static
- **Client Vite Dev**: http://localhost:9001 (don't access directly, use server port)
  - Only for development
  - Accessed through server proxy at port 9000
- **Website**: http://localhost:9002 (marketing site)
  - Independent static site
- **Database**: localhost:5432 (PostgreSQL)
- **API Docs**: http://localhost:9000/docs (FastAPI Swagger UI)

## Testing

- Server tests: Use pytest, located in `server/tests/`
- Client tests: Use Vitest + React Testing Library
- Website: Can use Vitest for component testing if needed
- Test files should be co-located with source files or in dedicated test directories

## Production Deployment

### Server (includes client)
1. Build client: `make build` (outputs to server/static)
2. Set `ENV=production` in server environment
3. Deploy server as Docker container (see `server/Dockerfile`)
4. Server serves both static files and APIs on port 9000
5. Requires PostgreSQL database
6. Set environment variables for production

### Website (Marketing Site)
- Build: `cd website && pnpm build`
- Deploy to Netlify, Vercel, or any static hosting platform
- No environment variables needed
- Can be deployed completely separately from server/client

```bash
cd website
pnpm build
# Deploy dist/ folder to Netlify, Vercel, etc.
```

## Key Differences from Previous Architecture

**Old Architecture:**
- Client on port 9000, Server on port 9001
- Client had Vite proxy to server
- Separate deployments

**New Architecture:**
- Server on port 9000, Client dev on port 9001
- Server proxies to Vite in development
- Server serves static files in production
- Single deployment (server includes client)
- Simpler production setup
- Better for monolithic deployment
